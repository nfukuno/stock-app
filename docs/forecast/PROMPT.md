# 開発セッション用 指示プロンプト

以下の「---」から下をそのまま新しいセッションに貼り付けてください。

---

あなたは `nfukuno/stock-app` リポジトリに「日足予想 & 類似度採点機能」を実装する担当です。

## 最初にやること
1. `git fetch origin claude/eager-galileo-esqukn` を実行し、そのブランチにある `docs/forecast/HANDOFF.md` を**全文読んでください**。要件・データ仕様・採点式・画面仕様・作業手順・完了条件はすべてそこに書いてあり、設計判断はユーザーと合意済みです。
   - 作業ブランチがまだ無い場合は `claude/eager-galileo-esqukn` から作成してください（引き継ぎ書を含めるため）。セッションで別の作業ブランチが指定されている場合は、そのブランチに `origin/claude/eager-galileo-esqukn` をマージしてから始めてください。
2. 既存コード（`app/main.py`, `app/line_notify/notify.py`, `app/utils.py`, `.github/workflows/notify.yml`, `requirements.txt`, `docker-compose.yml`）に目を通し、HANDOFF.md 1章の内容と食い違いがないか確認してください。

## 実装の方針
- HANDOFF.md **8章のフェーズ順**に進め、フェーズごとに `pytest` が通ることを確認してからコミットし、作業ブランチに push してください。
- 範囲は「予想入力（チャート上でドラッグ）＋ シナリオ・自信度・メモ ＋ 類似度スコア ＋ ベースライン比較 ＋ LINE 通知 ＋ 成績ダッシュボード」です。5分足の評価と米国株対応は**やりません**。
- 既存機能（`/` のドローダウン一覧と `notify.yml`）は壊さないでください。`app/main.py` への変更は router の追加と StaticFiles のマウントだけにしてください。
- 採点式・重み・閾値は HANDOFF.md 4章のとおりに実装し、定数は `config.py` にまとめてください。式を変える必要があると判断した場合は、勝手に変えずにユーザーに提案してください。
- 秘密情報（PAT、LINE トークン）をコードやコミットに含めないでください。
- CDN のライブラリはバージョンを固定してください（Lightweight Charts は v4.2 系。v5 は使いません）。
- UI の動作は、ローカルで uvicorn を起動して Playwright（Chromium はプリインストール済み。`playwright install` は実行しない）で実際に操作して確認してください。ドラッグ・保存・ダッシュボード表示のスクリーンショットを撮り、最後にユーザーへ共有してください。
- 動作確認用のダミー予想データはコミットしないでください。
- 判断に迷ったときは、まず HANDOFF.md を確認してください。それでも決められない場合だけユーザーに質問してください。

## 完了したら
- HANDOFF.md 9章の完了条件のチェックリストについて、それぞれの結果（できたこと、できなかったこと、確認方法）を報告してください。
- ユーザーの手作業（HANDOFF.md 10章：PAT の作成、main へのマージ、手動実行での確認）を、手順として日本語で案内してください。
- PR は、ユーザーに頼まれた場合だけ作成してください。
